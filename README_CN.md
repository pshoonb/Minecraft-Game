# RPG Core Prototype 0.3.0

Minecraft Java 1.21.1 / NeoForge 21.1.265 / Java 21。

RPG Core 保留原版生存、建造、挖矿、合成与经验系统；当前不设置职业、技能树或职业限制。

## 当前成长系统

- RPG 等级直接跟随 Minecraft 原版玩家经验等级。
- 属性点按玩家达到过的最高等级累计计算。消耗原版等级不会追回已经获得的属性点。
- 每次达到等级 x 的属性点奖励为 floor(x / 2) + min(100, x)。
- 累计属性点公式保持不变：P(x) = floor(x² / 4) + x(x + 1) / 2（0 到 100 级）；P(x) = floor(x² / 4) + 100x - 4950（100 级以上）。
- 玩家可自由分配七项属性：力量、生命值、防御力、挖掘速度、幸运、速度、跳跃高度。
- 玩家数据由服务器验证、按玩家独立保存，并同步给对应玩家；免费重置保留。

## 属性点软上限

属性效果使用以下曲线：

\[
E(p)=
\begin{cases}
p,&p\le25\\
25+15\ln(1+(p-25)/15),&p>25
\end{cases}
\]

前 25 个有效属性点按完整比例生效；之后逐渐降低每个新增点的边际收益，但不会在某个点数停止成长。

## 七项属性当前数值

| 属性 | 每个有效属性点的效果 |
|---|---:|
| 力量 | +0.20 攻击伤害 |
| 生命值 | +0.35 最大生命值 |
| 防御力 | +0.30 护甲；另有最终伤害减免、燃烧时间缩短和爆炸击退减弱 |
| 挖掘速度 | +2% 方块破坏速度，另加 +0.30 挖掘效率 |
| 幸运 | +0.20 原版 Luck，并提高矿石资源掉落数量 |
| 速度 | +1.2% 移动速度 |
| 跳跃高度 | +1.5% 起跳向上速度，并同步增加抗摔落能力 |

防御力的额外效果：
- 额外最终伤害减免：最高逐渐趋近 90%，在原版护甲、附魔和药水减伤处理后继续计算。
- 当额外减伤超过 60% 后，解锁原始伤害阈值免疫：每超过 1 个百分点，阈值增加 0.5 点原始伤害；额外减伤趋近 90% 时，阈值趋近 15 点。
- 低于当前阈值的单次原始伤害会在伤害计算开始前直接取消，不消耗护甲耐久或吸收值；达到或超过阈值的伤害正常进入护甲计算，再接受额外减伤。
- 绕过无敌判定的特殊伤害（例如虚空伤害）不受阈值免疫保护。
- 燃烧持续时间缩短：最高逐渐趋近 60%。
- 爆炸击退抵抗：最高逐渐趋近 70%。
- 护甲属性加成本身最多 +20；达到该值后，最终伤害减免、燃烧和爆炸保护仍继续成长。

跳跃与抗摔落：
- 跳跃起跳速度每个有效点增加 1.5%。
- 每个有效跳跃点增加 0.75 格安全摔落距离。
- 摔落伤害额外减免最高逐渐趋近 75%。
- 因此，跳跃点数增加时，安全摔落距离和摔落伤害减免也会一起增加。

## 幸运与矿物掉落

幸运除了增加原版 Luck 属性，还会在玩家挖掘矿石时增加资源掉落：
- 支持煤炭、钻石、绿宝石、青金石、红石、铜、铁、金、下界石英和远古残骸等矿石。
- 每 40 个有效幸运点提供一次额外掉落；不足 40 点的部分转化为下一次额外掉落的概率。
- 例如 10 点幸运约有 25% 概率让一次合格矿石挖掘多掉一份；40 点有效幸运保证增加一份额外掉落。
- 额外掉落复制原版已经计算出的资源结果，因此会与时运正常叠加。
- 精准采集直接掉落矿石方块时不会复制矿石方块，也不会复制额外经验。

## 按实际可达到等级评估

本项目将 100–150 级作为主要平衡区间，而不是按极少数玩家可能达到的 1000 级设计。

| 原版等级 | 累计属性点 | 平均分配到七项时，每项原始点数 | 每项有效点数约 |
|---:|---:|---:|---:|
| 10 | 80 | 11.4 | 11.4 |
| 100 | 7,550 | 1,078.6 | 89.0 |
| 150 | 15,675 | 2,239.3 | 100.0 |

投入 10 点到单项属性时：
- 力量：+2 攻击伤害。
- 生命值：+3.5 最大生命值。
- 防御力：+3 护甲、约 15% 额外最终伤害减免、约 15% 燃烧时间缩短、约 14% 爆炸击退抵抗。
- 挖掘速度：+20% 方块破坏速度、+3 挖掘效率。
- 幸运：+2 Luck；约 25% 概率增加一份合格矿石资源掉落。
- 速度：+12% 移动速度。
- 跳跃高度：+15% 起跳速度、+7.5 格安全摔落距离，并减少约 30% 摔落伤害。

这些是属性模型的理论值。实际挖掘速度取决于工具和方块；额外矿物掉落取决于每次挖掘的随机结果；实际跳跃高度与起跳速度不是线性关系。

## 加点按钮

每项属性提供 `+1`、`+10` 和 `+100`：
- 每次点击最多分配按钮对应的点数。
- 剩余可用点数不足时，会自动分配剩余的全部点数。
- 例如只剩 37 点时，点击 `+100` 会分配 37 点，而不是拒绝请求。

## 客户端与服务端

- 原版属性修正会同时在服务端和本地客户端应用，固定修正 ID 防止重复叠加。
- 跳跃高度在客户端预测和服务器端跳跃事件中同时调整。
- 抗摔落由安全摔落距离和摔落伤害倍率共同实现。
- 防御力在服务端的最终伤害阶段应用额外减伤。
- 挖掘速度同时使用 BLOCK_BREAK_SPEED 和 MINING_EFFICIENCY。
- 幸运额外掉落只在服务器端计算，避免客户端和服务器重复生成物品。

## 旧原型数据升级

- 力量的已分配点数保留。
- 旧原型中的敏捷、体质、智力和精神点数释放回可用属性点。
- 当前等级、历史最高等级和累计属性点公式不变。

## 建议测试

1. 分别投入 10 点到每种属性，比较实际变化。
2. 跳跃属性投入 10、25、50 点，比较跳跃高度及摔落伤害。
3. 幸运分别投入 10、40、80 点，挖掘多组煤炭和钻石矿，比较掉落总量；单次挖掘的结果有随机性。
4. 测试普通矿石掉落与精准采集，确认只额外复制资源，不复制矿石方块。
5. 分别测试普通攻击、爆炸和燃烧伤害，检查防御力。
6. 测试 +1、+10、+100，确认剩余点数不足时会自动分配全部剩余点数。
7. 重置、重新登录和死亡重生后，确认效果能撤销及恢复。
